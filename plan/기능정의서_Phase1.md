## SCR-00 · 로그인

| 항목 | 내용 |
|------|------|
| 목적 | 소셜 계정으로 사용자 인증. 신규/기존 사용자 분기 |
| 진입 | 앱 최초 실행 또는 로그아웃 상태 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-00-01 | Apple로 로그인 | Apple Sign In. 성공 시 신규/기존 여부 판단 |
| F-00-02 | Google로 로그인 | Google OAuth. 성공 시 신규/기존 여부 판단 |
| F-00-03 | 신규/기존 분기 | 신규 → SCR-02(온보딩) / 기존 → SCR-08(홈) |

**비즈니스 규칙**
- 이메일·비밀번호 입력 없음. 소셜 버튼만 제공
- 인증 토큰은 기기 내 SecureStore에 저장 (AsyncStorage 아님)
- 로그인 상태가 유효하면 앱 재실행 시 SCR-00 건너뛰고 SCR-01로 진입
- 기존 사용자 판단 기준: 온보딩 완료 여부 (서버 또는 AsyncStorage에 프로필 데이터 존재)

> ⚠️ 소셜 로그인은 Firebase Auth 또는 Supabase Auth 사용 필요 (백엔드 필요). Phase 1에서 백엔드 범위 결정 시 개발자와 협의 필요.

**예외 처리**
- 소셜 로그인 실패(네트워크 오류) → "로그인에 실패했어요. 다시 시도해주세요" 토스트
- 소셜 계정 연결 거부 → 로그인 화면 유지

## SCR-02 · 온보딩 1 — 이름·성별

| 항목 | 내용 |
|------|------|
| 목적 | 인사말 개인화, 옷차림 추천 스타일 차별화를 위한 기본 정보 수집 |
| 진행률 | 1/5 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-02-01 | 이름 입력 | 텍스트 입력 (2~10자) |
| F-02-02 | 성별 선택 | 남성 / 여성 / 선택 안 함 (3지선다) |
| F-02-03 | 다음 버튼 | 이름 입력 완료 시 활성화. 탭 시 SCR-03 이동 |

**비즈니스 규칙**

- 이름은 브리핑 인사말에 사용: `{이름}님, 좋은 아침이에요!`

**예외 처리**
- 이름 공백만 입력 시 → 다음 버튼 비활성화 유지

## SCR-03 · 온보딩 2 — 체감 온도

| 항목 | 내용 |
|------|------|
| 목적 | 동일 기온에서 개인화된 옷차림 추천을 위한 체감 온도 기준 수집 |
| 진행률 | 2/5 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-03-01 | 체감 온도 선택 | 더위 많이 탐 / 보통 / 추위 많이 탐 (3지선다) |
| F-03-02 | 다음 버튼 | 선택 완료 시 활성화. 탭 시 SCR-04 이동 |
| F-03-03 | 이전 버튼 | SCR-02로 돌아가기 |

**비즈니스 규칙**
- 옷차림 추천 시 체감 온도 반영 로직:
  - 더위 많이 탐: 실제 온도 +3°C 기준으로 추천
  - 추위 많이 탐: 실제 온도 -3°C 기준으로 추천
  - 예) 실제 24°C / 더위 많이 탐 → "반팔로도 충분해요"
  - 예) 실제 24°C / 추위 많이 탐 → "얇은 니트나 긴팔 추천해요"

## SCR-06 · 온보딩 5 — 알림 설정

| 항목 | 내용 |
|------|------|
| 목적 | 브리핑 수신 시간 및 알림 스타일 설정 |
| 진행률 | 5/5 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-06-01 | 아침 브리핑 시간 설정 | 시간 피커. 기본값 07:30 |
| F-06-02 | 알림 스타일 선택 | 간단하게 / 디테일하게 (2지선다) |
| F-06-03 | 알림 권한 요청 | iOS 알림 권한 팝업 표시 |
| F-06-04 | 시작하기 버튼 | 프로필 저장 → 알림 스케줄 등록 → SCR-07(채팅) 이동 |
| F-06-05 | 이전 버튼 | SCR-05로 돌아가기 |

**비즈니스 규칙**
- 알림 스타일
  - 간단하게: "오늘 맑음 24°C. 일정 2개. 사원증 챙기세요."
  - 디테일하게: "지영님, 좋은 아침이에요! 오늘 서울 맑고 24°C예요. 더위 많이 타시니까..."
- 시작하기 탭 시 처리 순서:
  1. 프로필 데이터 AsyncStorage 저장
  2. 아침 브리핑 알림 스케줄 등록
  3. SCR-07 이동

**예외 처리**
- 알림 권한 거부 시 → 알림은 등록하지 않음. 앱 진입은 허용. 설정에서 나중에 활성화 가능

## SCR-07 · 채팅 (메인 홈)

| 항목 | 내용 |
|------|------|
| 목적 | AI 비서와 대화, 자연어로 일정·할 일 등록 |
| 진입 | 온보딩 완료 후 기본 화면 / 하단 탭 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-07-01 | 채팅 메시지 표시 | AI 메시지 (왼쪽), 사용자 메시지 (오른쪽) 버블 형태 |
| F-07-02 | 텍스트 입력 | 하단 입력창. 전송 버튼 |
| F-07-03 | AI 응답 생성 | Claude API 호출. 사용자 메시지 → AI 응답 |
| F-07-04 | 일정 파싱 및 등록 | 메시지에서 일정 의도 감지 시 캘린더 저장 후 확인 메시지 출력 |
| F-07-05 | 할 일 파싱 및 등록 | 메시지에서 할 일 의도 감지 시 할 일 저장 후 확인 메시지 출력 |
| F-07-06 | 브리핑 배너 | 앱 진입 시 오늘 브리핑 요약 배너 상단 노출. 탭 시 SCR-08 이동 |
| F-07-07 | 첫 인사 메시지 | 앱 최초 진입 시 AI가 먼저 인사 메시지 출력 |

**비즈니스 규칙**

#### AI 페르소나 정의
> ⚠️ 아래 항목은 정책 담당자가 확정 후 기입

| 항목 | 내용 (확정 필요) |
|------|-----------------|
| AI 이름 | (예: 루나 / 하루) — 미정 |
| 말투 | 따뜻하고 친근한 존댓말. 딱딱하지 않게. 이모지 적당히 사용 |
| 금지 표현 | 반말, 과도한 격식체, 명령형 |
| 인사 패턴 | `{이름}님, 좋은 아침이에요!` — 이름은 온보딩 프로필에서 주입 |
| 첫 메시지 | `{이름}님, 저는 {AI이름}이에요. 일정·준비물·할일 뭐든 말씀해주세요 😊` |

#### 의도 파싱 케이스

| type | 조건 | 처리 | 응답 예시 |
|------|------|------|-----------|
| `event` | 날짜·시간 포함된 일정 의도 | 캘린더 저장 | "금요일 2시 치과 예약 저장했어요 🦷 출발 알림도 설정할까요?" |
| `task` | 완료가 필요한 할 일 의도 | 할일 저장 | "내일 마감 기획서 제출, 할일에 추가했어요!" |
| `essential` | 챙겨야 할 물건 언급 | 챙길 것들에 추가 | "우산 챙길 것들 목록에 추가했어요 ☂️" |
| `chat` | 위 3가지 외 일반 대화 | AI 답변만 | (자유 응답) |
| `ambiguous` | 일정인지 할일인지 불분명 | 사용자에게 확인 질문 | "이걸 일정으로 등록할까요, 할일로 등록할까요?" |

#### 대화 기록 정책

| 항목 | 내용 |
|------|------|
| 보관 개수 | 최근 20개 메시지 (API 비용·속도 균형) |
| 저장 위치 | AsyncStorage (로컬, Phase 1) |
| 초기화 조건 | 사용자가 직접 초기화 버튼 누를 때만. 앱 재실행 시 유지 |

#### 개인화 주입 방식
AI 호출 시 시스템 프롬프트에 온보딩 프로필 데이터를 자동 삽입:

```
당신은 {AI이름}이에요. {이름}님의 개인 비서예요.
- 성별: {성별}
- 체감 온도: {체감온도} (더위 많이 탐 / 보통 / 추위 많이 탐)
- 직업: {직업유형}
- 출근 시간: {출근시간}
- 알림 스타일: {알림스타일}
```

→ 동일한 날씨도 체감 온도에 따라 다른 옷차림을 추천하게 됨

**예외 처리**
- Claude API 응답 실패 시 → "잠시 연결이 안 됐어요. 다시 말해볼까요?" 출력
- 메시지 전송 중 로딩 인디케이터 표시 (버블 점 3개 애니메이션)
- 의도 파싱 실패 시 → `chat` 타입으로 폴백 처리 (기능 오작동보다 안전한 일반 대화가 낫기 때문)

## SCR-08 · 브리핑

| 항목 | 내용 |
|------|------|
| 목적 | 매일 아침 날씨·일정·준비물 통합 브리핑 제공 |
| 진입 | 아침 알림 탭 / 채팅 화면 상단 배너 탭 |

### 기능

| 기능 ID | 기능명 | 설명 |
|---------|--------|------|
| F-08-01 | 날씨 정보 표시 | OpenWeatherMap API 호출. 현재 날씨, 기온, 날씨 상태 아이콘 |
| F-08-02 | 옷차림 추천 표시 | 기온 + 체감 온도 설정 + 성별 → AI 추천 문구 생성 |
| F-08-03 | 환경 지표 표시 | 미세먼지 등급 · 습도 · 자외선 지수 3종 카드 형태 표시 |
| F-08-04 | 오늘 일정 목록 표시 | 앱 내 저장된 당일 일정 목록. 없으면 "오늘 일정이 없어요" |
| F-08-05 | 챙길 것들 체크리스트 | 기본 등록 준비물 + 환경 조건 자동 항목 포함 체크박스 목록 |
| F-08-06 | 체크 완료 처리 | 항목 탭 시 체크 상태 토글 (당일에만 유효, 다음 날 초기화) |
| F-08-07 | 채팅으로 이동 | 하단 버튼 탭 시 SCR-07 이동 |
| F-08-08 | 브리핑 데이터 갱신 | 화면 진입 시 날씨·대기오염 API 호출, 일정 데이터 최신화 |

**비즈니스 규칙**
- 날씨 API 호출 시 기기 위치 권한 사용. 권한 없을 경우 기본 지역(서울) 사용
- 옷차림 추천 로직 (온도 기준):
  - ~4°C: 패딩, 두꺼운 코트
  - 5~11°C: 코트, 두꺼운 자켓
  - 12~16°C: 자켓, 가디건
  - 17~19°C: 얇은 자켓, 긴팔
  - 20~23°C: 긴팔, 얇은 가디건
  - 24~27°C: 반팔, 얇은 자켓
  - 28°C~: 반팔, 민소매
- 체감 온도에 따라 기준 온도 ±3°C 조정 후 위 기준 적용

#### 환경 지표 정책

**데이터 소스**

| 지표 | API | 항목 |
|------|-----|------|
| 미세먼지 (PM10 / PM2.5) | OpenWeatherMap Air Pollution API | `list[0].components.pm10`, `pm2_5` |
| 습도 | OpenWeatherMap Current Weather | `main.humidity` (%) |
| 자외선 지수 | OpenWeatherMap One Call API | `current.uvi` |

**미세먼지 등급 기준 (WHO/한국 환경부 기준)**

| 등급 | PM10 (㎍/㎥) | PM2.5 (㎍/㎥) | 표시 | 자동 챙길 것 |
|------|------------|--------------|------|-------------|
| 좋음 | 0~30 | 0~15 | 😊 좋음 | — |
| 보통 | 31~80 | 16~35 | 😐 보통 | — |
| 나쁨 | 81~150 | 36~75 | 😷 나쁨 | **마스크 자동 추가** |
| 매우 나쁨 | 151~ | 76~ | 🚨 매우 나쁨 | **마스크 자동 추가** |

**습도 안내 기준**

| 습도 | 표시 | 안내 문구 |
|------|------|-----------|
| ~39% | 🏜️ 건조 | "건조해요, 수분 보충 챙기세요" |
| 40~69% | — 표시 없음 | 습도 수치만 표기 |
| 70~79% | 💦 습함 | "습도 높아요, 땀 많이 날 수 있어요" |
| 80%~ | 💦 매우 습함 | "매우 습해요, 여분 옷 챙기면 좋아요" |

**자외선 지수 (UV Index) 기준**

| UV Index | 등급 | 표시 | 자동 챙길 것 |
|----------|------|------|-------------|
| 0~2 | 낮음 | — | — |
| 3~5 | 보통 | ☀️ 보통 | — |
| 6~7 | 높음 | 🧴 높음 | **썬크림 자동 추가** |
| 8~10 | 매우 높음 | 🧴 매우 높음 | **썬크림 자동 추가** |
| 11~ | 위험 | ⚠️ 위험 | **썬크림 자동 추가** |

**챙길 것들 자동 항목 정책**
- 미세먼지 나쁨 이상 → "마스크 😷" 자동 추가 (색상 강조: 노란색)
- 자외선 높음 이상 → "썬크림 🧴" 자동 추가 (색상 강조: 노란색)
- 자동 추가 항목은 사용자 수동 등록 항목보다 아래에 표시
- 탭하여 체크 가능. 다음 날 초기화
- 자동 항목 옆 "(오늘 미세먼지·자외선↑)" 등 조건 힌트 텍스트 표시
- 챙길 것들 체크 상태는 날짜 기준으로 관리 (매일 자정 초기화)

**예외 처리**
- 날씨 API 실패 시 → "날씨 정보를 불러오지 못했어요" 표시. 나머지 콘텐츠는 정상 표시
- 인터넷 미연결 시 → 마지막 캐시된 날씨 데이터 표시 (캐시 없으면 안내 문구)

**비즈니스 규칙**
- 오늘 마감인 할 일: 상단 고정, Primary 색상 강조
- 완료된 할 일: 취소선 처리, 목록 하단으로 이동
- 지난 일정: 회색 처리
- 캘린더 점(dot) 색상: 일정 있으면 Primary 색상 / 할 일 마감이면 보조색
- 캘린더에서 날짜 탭 시 → 해당 날의 일정과 할 일 마감 목록 함께 표시
- 캘린더 기본 선택 날짜는 오늘

**비즈니스 규칙 (채팅 CRUD)**
- 채팅에서 "치과 예약 삭제해줘" → AI가 목록에서 해당 항목 검색 후 삭제 확인 메시지 출력 → 사용자 확인 시 삭제
- 채팅에서 "금요일 회의 시간 3시로 바꿔줘" → AI가 항목 검색 후 수정 처리
- 채팅 수정/삭제는 항목이 특정되지 않으면 → AI가 "어떤 일정이에요?" 되물음

**예외 처리**
- 선택한 날짜에 일정·할 일 없을 경우 → "이 날은 일정이 없어요. 채팅으로 추가해보세요"
- 수정 모달에서 날짜를 과거로 변경 → 경고 없이 허용 (과거 일정 기록 용도)

## 개인화 정책

### 개인화 구조

개인화는 별도 엔진 없이 **온보딩 데이터를 AI 호출 시 프롬프트에 주입**하는 방식으로 동작한다.

```
온보딩 수집 → AsyncStorage 저장 → AI 호출 시 시스템 프롬프트에 자동 삽입 → 개인화된 응답
```

### 시스템 프롬프트 주입 템플릿

> ⚠️ AI 이름 확정 후 `{AI이름}` 교체 필요

```
당신은 {AI이름}이에요. {이름}님의 개인 비서예요.
항상 따뜻하고 친근한 존댓말로 말해요. 이모지는 자연스럽게 적당히 써요.

[사용자 정보]
- 이름: {이름}
- 성별: {성별}
- 체감 온도: {체감온도}  (더위 많이 탐 / 보통 / 추위 많이 탐)
- 직업: {직업유형}  (직장인 / 학생 / 기타)
- 출근 시간: {출근시간}
- 알림 스타일: {알림스타일}  (간단하게 / 디테일하게)
```

### 개인화 항목별 적용 정책

| 개인화 항목 | 데이터 출처 | 적용 방식 | 예시 |
|------------|------------|----------|------|
| 이름 호칭 | 온보딩 | 인사말·확인 메시지에 삽입 | "지영님, 좋은 아침이에요!" |
| 옷차림 스타일 | 온보딩 (성별) | AI 프롬프트 주입 → 성별에 맞는 아이템 추천 | 여성: 블라우스·원피스 / 남성: 셔츠·슬랙스 언급 |
| 온도 기준 보정 | 온보딩 (체감온도) | 날씨 API 기온에 ±3°C 보정 후 옷차림 판단 | 더위 많이 탐: 24°C → 27°C 기준으로 추천 |
| 직업별 표현 | 온보딩 (직업) | AI 프롬프트 주입 → 상황에 맞는 단어 사용 | 직장인: "출근·회의" / 학생: "등교·수업" |
| 알림 문구 길이 | 온보딩 (알림 스타일) | 브리핑 생성 시 분기 | 간단: 1줄 요약 / 디테일: 3~5줄 상세 |
| 출근 시간 기반 알림 | 온보딩 (출근시간) | Phase 2 출발 알림 역산 기준으로 사용 | 9:00 출근 → 8:20 출발 알림 |

### 개인화 레이어별 구현 시점

| 레이어 | 내용 | Phase |
|--------|------|-------|
| 레이어 1 · 프로필 기반 | 온보딩 입력값 → 프롬프트 주입. 즉시 반영 | **Phase 1** |
| 레이어 2 · 패턴 기반 | 반복 일정 감지, 자주 챙기는 준비물 자동 제안 | Phase 2 |
| 레이어 3 · 명시적 학습 | 사용자 피드백으로 AI 취향 조정, 설정에서 확인·수정 | Phase 3 |

### 데이터 흐름 다이어그램

```
[온보딩 화면]
  이름·성별·체감온도·직업·출근시간·알림스타일 입력
         ↓ 저장
[AsyncStorage: user_profile]
         ↓ 읽기 (AI 호출마다)
[채팅 / 브리핑 화면]
  시스템 프롬프트에 프로필 값 삽입 → Claude API 호출
         ↓
  개인화된 응답 출력
```

### 개인화 관련 예외 처리

| 상황 | 처리 방식 |
|------|-----------|
| 프로필 미완성 상태로 채팅 접근 | 기본값으로 동작. 이름 없으면 "안녕하세요!" 사용 |
| 사용자가 프로필 수정 시 | 다음 AI 호출부터 즉시 반영 (재시작 불필요) |
| 성별 "선택 안 함" 선택 시 | 성별 중립적 표현 사용 ("편한 옷차림 추천" 등) |
